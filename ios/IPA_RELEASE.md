# Выпуск IPA для IPA Shelf

Общая папка: `~/Library/Mobile Documents/com~apple~CloudDocs/IPA Shelf` (iCloud Drive → **IPA Shelf**).

После обычных проверок проекта и повышения номера сборки запускайте `tools/release-ipa.sh`. Команда собирает Release для iPhone, сохраняет локальную IPA и публикует её в общей папке. Для уже готовой IPA: `python3 tools/ipa-release.py --publish-only /полный/путь/приложение.ipa`.

- `--no-cloud`: только сборка и локальная упаковка.
- `--force`: явно разрешить замену той же version/build другим содержимым или откат.
- `IPA_SHELF_DIR`: переопределить общую папку, например для проверки без iCloud.
- Имя в общей папке: `<BundleID>--<version>--<build>.ipa`, все поля читаются из настоящего Info.plist архива.
- **«Ошибка выпуска: File is not a zip file» при готовой локальной IPA** — прошлая сборка в iCloud выгружена с Mac (`ls -lO` показывает `dataless`), и скрипт не может прочитать её версию для проверки отката. Так было 24 октября 2026 со сборкой 9. Лечение: `brctl download "<папка IPA Shelf>/<BundleID>--<version>--<build>.ipa"`, дождаться, пока из `ls -lO` уйдёт `dataless`, затем `python3 tools/ipa-release.py --project-root <ios> --publish-only build/dist/LoriLocal-unsigned.ipa` — без пересборки.
- Системный диск почти полон: каталог сборки выпуска передаётся абсолютным путём на внешний диск — `tools/release-ipa.sh --derived-data /Volumes/Movis/Mac-data/LoriWork/dd-release` (последний `--derived-data` побеждает).
- С 24 октября 2026 (сборка 10) в IPA есть расширение `PlugIns/RecordingActivity.appex` (Live Activity записи). IPA Shelf переподписывает расширения с его сборки 11; если установка на телефоне упадёт на подписи расширения — дело в профиле, а не в приложении.
- Сначала выполняются полная запись временного `.uploading`, проверка ZIP и SHA-256, затем атомарное переименование в `.ipa`.
- Только после успешной публикации удаляются предыдущие управляемые файлы этого же Bundle ID. IPA других приложений не удаляются. Одновременные публикации одного приложения сериализованы локальной блокировкой.
- В общую папку не кладут исходники, сертификаты или резервные копии. Это личные сборки: в некоторых проектах внутри есть личные настройки/ключи.
- Старые отдельные папки больше не являются местом выпуска. Сохранившиеся там файлы — архивные копии.

На iPhone один раз выберите **IPA Shelf** в системном выборе папки менеджера. Путь на Mac нельзя превратить в разрешение iOS: доступ выдаётся через picker на телефоне. Синхронизация iCloud может занять время.

Факт появления IPA в папке не означает, что её можно подписать присланным профилем. Нужны допустимые сертификат, профиль и entitlements, а также поддержка расширений. Уточнение от 23.09: signing application-identifier явного профиля может отличаться от сохранённого CFBundleIdentifier; прежняя строгая проверка исправлена в IPA Shelf build 3 после теста на физическом iPhone. Текущий IPA Shelf Probe пока не подписывает extensions; OTA-путь на iOS 27 остаётся экспериментальным. Эти скрипты готовят неподписанные IPA для последующей подписи, не меняют Bundle ID и не устанавливают приложения.
