## Что изменено

### 1. Продолжение работы

- `TranscriptionJob`: устойчивый ID запуска и снимок настроек при постановке в очередь. API-ключи в снимок не входят. Очередь, включая ещё не начатые задания, записывается атомарно на диск.
- `InterruptedRecords`: новый архив сохраняет новые задания и legacy-записи отдельно. Старые облачные записи без снимка не получают автоматическое разрешение на повтор. Новые продолжаются с исходным движком, сервером, моделью и режимом.
- `BackgroundTranscriptionTransport`: file upload/download через системную background URLSession, переподключение к имеющемуся заданию, сохранение успешного ответа, стабильный ID запроса. Отмена ожидания Swift при suspension не отменяет системную передачу; явная отмена пользователем отменяет передачу и удаляет локальные файлы задания.
- Multipart boundary и имена временных файлов стабилизированы для повторов. Gemini Files upload учитывает содержимое аудио, а не UUID временного FLAC. Удаление Gemini Files перенесено на завершение/отмену задания; очистка best effort, при сетевой ошибке действует срок хранения провайдера.
- `TranscriptionRunway`: принятая заявка больше не выдаётся за уже предоставленное фоновое выполнение. По окончании доступного фонового времени работа становится прерванной с сохранённым заданием. Возврат в приложение и восстановление сети возобновляют работу; для временных сетевых ошибок предусмотрены три ограниченных повтора.
- `LocalTranscriptCheckpoint`: GigaAM и Whisper сохраняют завершённые части, слова и времена; незавершённая часть может считаться повторно. Gemini сохраняет свои существующие checkpoints. Для Apple Speech отдельного checkpoint по частям нет.

### 2. Автоматические заголовки и описания

- Запуск привязан к сохранению результата сервисом, а не к `ContentView.onChange`.
- Очередь `SummaryRunner` сохраняется на диск, не отбрасывает старые записи после четырёх элементов и восстанавливается после перезапуска.
- При открытии сканируются сохранённые расшифровки без описания; отсутствие модели/памяти оставляет задание ожидающим. Установка модели и возвращение в Lori повторяют попытку.
- MLX запускается только на переднем плане после освобождения ASR; начало новой расшифровки отменяет текущую генерацию описания. Задание остаётся в очереди.
- Ручное имя сохраняется, недостающее описание генерируется. Запись результата на диск должна удаться до удаления задания из очереди.
- В настройках заголовков видна причина ожидания/ошибка. Тексты короче установленного порога 80 символов по-прежнему не обрабатываются.

### 3. Исторический режим

- Файл расшифровки содержит отдельное поле `_Режим: …_`, записанное из снимка задания.
- Экран показывает модель и сохранённый режим. Изменение настроек не меняет старый результат; записи без поля остаются без известного режима.
- Разбор имени сохраняет подчёркивания: `scribe_v2` остаётся `scribe_v2`.
- Markdown экспорт сохраняет режим отдельным полем; PDF выводит полное имя движка и режим. Сокращение имени для экрана не применяется к экспорту.

## Что нельзя считать доказанным

- Реальные Home/lock, предоставление BGContinuedProcessingTask, upload/ответ после suspension и возврат на iPhone.
- Реальная локальная генерация summary на последней сборке телефона.
- Распознавание длинного аудио GigaAM/Whisper после возврата на устройстве, нагрев, память и батарея.
- Отсутствие повторного счёта у провайдера при неоднозначном сетевом timeout. Сохранённый ответ и переподключение уменьшают риск повтора, но без провайдерского idempotency/webhook нельзя обещать ровно один платный запрос при любом обрыве.
- Продолжение после изменения исходного аудиофайла извне: локальный checkpoint привязан к заданию и границам частей, содержимое аудио отдельно не хэшируется.
